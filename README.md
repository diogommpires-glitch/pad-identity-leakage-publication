# Identity leakage audit tools

Source-available code for investigating identity overlap in presentation-attack
and deepfake benchmark splits. Original code is licensed for non-commercial
use under [PolyForm Noncommercial 1.0.0](LICENSE); see
[LICENSING.md](LICENSING.md) for third-party and earlier-version terms.

This code-only snapshot includes standalone overlap and split-audit tools,
research experiment source and offline security regressions. It deliberately
omits all per-sample scores, subject and sample path records, split indices,
audit pools, result files, supplementary archives, images, external code,
models and previous Git history. It cannot reproduce the paper's tables or
validate reported experimental results from the files supplied here.

## Standalone overlap calculation

`tool/compute_L.py` uses only Python's standard library. Supply your own
authorised JSON arrays of paths, or objects with a `path` field:

```sh
python tool/compute_L.py TRAIN.json TEST.json --key celeba
python tool/compute_L.py TRAIN.json TEST.json --key client
python tool/compute_L.py TRAIN.json TEST.json --key video
```

For extracted identity sets A (train) and B (test), the reported asymmetric
metric is `L = |A intersect B| / max(1, |B|)`. The `celeba` rule extracts a
numeric filename prefix, `client` extracts Replay-Attack-style client tokens,
and `video` removes trailing frame indices. These are naming conventions,
not proof that a path identifies a person correctly. Inspect the rule against
your dataset protocol before interpreting the result. Empty test input yields
zero under the preserved formula and does not establish split integrity.

`tool/split_leakage_audit.py` provides manifest stamping and overlap audits.
`tool/replay_rekey_check.py` requires an explicit compatible path-record array;
its original audit pool is omitted. `tool/leakage_metric.py` is the integrated
research implementation and imports `pad.metrics` from the original research
environment, which is not bundled in this repository.

## Offline checks and research source

Use Python 3.11 and a separate environment:

```sh
python -m venv .venv
# Activate .venv, then:
python -m pip install -r requirements-test.txt
python -m pytest -q
```

The tests use generated paths and temporary tensor checkpoints, reject
executable pickle checkpoints, check explicit archive configuration and capture
notification requests locally. They do not send notifications, access datasets,
download weights or train models. CI runs these same offline checks.

The `experiment/` scripts preserve the research calculations and security
guards, including tensor-only checkpoint loading. They require external
datasets, supplementary records, third-party detector code or CUDA resources
that are not provided here. Historical comments and numerical examples describe
the original study; they are not results reproduced or revalidated by this
snapshot. Review and configure all external prerequisites before deliberate use.

Notifications are disabled unless both `DODO_NTFY_TOPIC` and `DODO_NTFY_TOKEN`
are configured locally. No personal topic or populated credentials are supplied.
Dataset permissions and third-party terms remain separate from the project
licence. Do not publish personal path records generated by later experiments.
